2. Abstract

VERA (Volunteer Emergency Response Alliance) is a full-stack web platform that centralizes emergency assistance and resource coordination in Bangladesh. It connects citizens in need with volunteers, blood donors, NGOs, hospitals, and administrators through one role-based system.

The MVP is built with a React (Next.js) frontend and a FastAPI (Python) backend, using JWT authentication and a REST API. Core workflows include emergency requests, blood donor matching, shelters, incident reporting, donations and campaigns, volunteer opportunities, disaster coverage maps, notifications, and an in-app Gemini-powered assistant (VERA Bot) that can query live platform data. The production stack is deployed as Vercel (frontend) + Railway (API) + Supabase PostgreSQL (database).

3. Introduction & Motivation

Bangladesh faces frequent medical emergencies and natural disasters. Today, people often seek help through Facebook groups, WhatsApp chats, and informal networks. These channels are slow, unverified, and hard to coordinate—especially when many organizations respond independently.

VERA replaces that fragmentation with a shared digital platform: submit requests, match donors, track shelters and coverage, manage volunteers, and keep donation records transparent.

5. Objectives & Scope

5.1 Objectives

  1. Provide one platform for emergency and resource coordination
  2. Connect help-seekers with volunteers, donors, NGOs, and hospitals
  3. Reduce response time for medical and disaster emergencies
  4. Match blood requests to available donors with notifications
  5. Support transparent donations and fundraising campaigns
  6. Enable location-aware search, shelters, incidents, and coverage tracking
  7. Support volunteer recruitment, applications, and certificates

5.2 In Scope (MVP)

  • Registration, login, and role-based access (citizen, volunteer, donor, NGO, hospital, admin)
  • Emergencies, blood requests, shelters, incidents, resources, donations, campaigns
  • Volunteer opportunities, applications, certificates
  • Notifications, nearby search, coverage map, admin reports
  • VERA Bot assistant with live database tools

5.3 Out of Scope (Current Phase)

  • Native mobile apps
  • Live payment gateway for donations
  • Deep government system integrations
  • Fully offline disaster-mode networking

8. System Architecture & Tech Stack

VERA uses a three-tier client–server design:

TierTechnologyResponsibility
PresentationNext.js 16, React 19, Tailwind CSS 4, LeafletUI, routing, maps (Vercel)
ApplicationFastAPI, Uvicorn, Pydantic, SQLAlchemyBusiness logic, JWT auth, validation (Railway)
DataSQLite (local) / Supabase PostgreSQL (prod)Persistence (Alembic migrations)
AIGoogle Gemini (gemini-flash-lite-latest)VERA Bot chat + DB tool calling

Communication is JSON over HTTP REST. Protected endpoints require Authorization: Bearer <JWT>. Auth remains VERA JWT (not Supabase Auth); Supabase is used as the hosted Postgres database only. 

Browser → Vercel (Next.js)
              │  NEXT_PUBLIC_API_URL
              ▼
         Railway (FastAPI)
              │  DATABASE_URL (pooler + sslmode=require)
              ▼
         Supabase (PostgreSQL)

Course requirement note: Backend is FastAPI (Python). Frontend is React via the Next.js App Router.

10. Agentic AI Assistant (VERA Bot)

VERA Bot is a floating assistant available across the website. It uses the Google Gemini API through a FastAPI endpoint (/api/v1/assistant/chat and streaming /chat/stream).

  • Answers in simple language for everyday users
  • Uses live platform snapshot (counts) plus database tools for lists/details
  • Can look up emergencies, blood requests/donors, shelters, incidents, resources, campaigns, volunteers, coverage, and user alerts
  • For life-threatening cases, advises calling 999 first

13. Deployment & How to Run

13.1 Live production URLs (evaluation)

ComponentHostURL
Website Vercel https://vera-frontend-indol.vercel.app
API Railway https://vera-production-117c.up.railway.app
Database Supabase (Postgres) Project mwsqekmbqrblaglffclb (ap-southeast-2)

Frontend env: NEXT_PUBLIC_API_URL points at the Railway API. Backend env: DATABASE_URL (Supabase pooler + sslmode=require), SECRET_KEY, CORS_ORIGINS, GEMINI_API_KEY, GEMINI_MODEL=gemini-flash-lite-latest. Railway builds from the repo-root Dockerfile / railway.toml.

npm run dev

14. Limitations & Future Work

  • No live payment gateway (donations tracked in-app)
  • Email/SMS notifications optional and env-gated
  • No native mobile apps yet
  • Future: stronger offline resilience, richer analytics, government integrations

15. Conclusion

VERA delivers a working emergency-response MVP that meets the course stack requirement (FastAPI + React) and demonstrates end-to-end features from authentication through coordination workflows, maps, and an AI assistant grounded in live data. The production deployment on Vercel, Railway, and Supabase shows the system running beyond localhost. The project shows how a centralized platform can improve speed, coordination, and transparency for emergency assistance in Bangladesh.
